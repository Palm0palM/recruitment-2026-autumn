# versions/ —— 优化过程记录

本目录按「一个版本一个目录」记录题目优化过程中的每一次可复现的进展。
它是笔试 PPT 的事实来源：**PPT 里出现的每一个数字，都应该能在这里找到对应的命令、代码状态和原始输出。**

## 记录约定

```
versions/
├── README.md                  ← 本文件：约定 + 总览表
├── V0-baseline/               ← 原始朴素实现（tag: v0-baseline）
│   ├── README.md              ← 结论、环境、结果表、瓶颈分析
│   └── raw/                   ← 原始测量输出（bench/validate/perf 的文本）
├── V1-<一句话优化名>/
│   ├── README.md              ← 做了什么 / 为什么 / 收益 / 正确性 / 复现命令
│   └── raw/
└── ...
```

一个版本目录里必须包含：

1. **代码状态**：git tag（`v1-something`），以及相对上一版的 `git diff --stat`。
2. **做了什么**：改动的关键点（配置、数据结构、并行度、库），以及为什么这样改。
3. **正确性**：四组用例的 `max|err|` 与 `PASS/FAIL`（必须来自官方 `validate.py` 或 `scripts/bench.py` 全量模式）。
4. **性能**：四组用例耗时（3~5 次取最小值）、相对 V0 的加速比、相对上一版的增量收益。
5. **复现命令**：完整可粘贴的命令行（含 slurm 提交方式）。
6. **profile 证据**：perf/火焰图/阶段计时（至少给出热点占比）。
7. **踩坑与结论**：这一版学到的东西、失败的尝试（失败的也要记，PPT 里很值钱）。

## 测量口径（必须统一，否则数字不可比）

- 平台：**七边形集群计算节点**（`slurm` 作业，1 节点 16 核），本地数字仅作趋势参考。
- 计时：`validate.py` 报告的「整体进程 wall time，3 次最小值」（含读 49 MB PCM、写 197 MB 输出）。
- 加速比分母：同一作业内的 `librosa`（`validate.py` 自带），以及 `V0` 的实测值。
- 正确性容差：`rtol=1e-3, atol=1e-4`（题目给定）。
- 环境记录：节点名、`nproc`、编译命令、库版本（fftw/openblas/gcc）必须写进每个版本。

> 口径提醒：
> * 本地 15 GiB 内存机器上 default 全量会因功率谱 6.3 GiB 产生换页；集群节点 1 TB 内存没有这个问题，
>   所以**跨平台只比「相对 V0 的倍数」，不混用绝对秒数**。

>   即使 V1 之后上集群，也优先用 `small_mels` 或截断输入。
