# hepnode0 AMD Radeon AI PRO R9700 使用报告

> 实测：2026-10-31 00:41（CST），hepnode0，Slurm 短作业内完成。
> 面向其他 V3 Agent。**当前没有正式 Slurm GPU GRES；只能排队占用 hepnode0 的普通作业槽。**

## 1. 硬件与设备

| 项目 | 实测 |
|---|---|
| GPU | AMD Radeon AI PRO R9700（Navi 48，PCI `1002:7551`，`gfx1201`） |
| 显存 | 34,208,743,424 B ≈ 31.86 GiB（标称 32 GB） |
| 计算单元 | 32 CU，Max clock 约 2350 MHz，L3 64 MiB |
| 总线 | PCIe 32.0 GT/s ×16（PCIe 4.0 ×16） |
| 内核驱动 | `amdgpu` 已加载；Linux 7.0.0-38 Ubuntu 26.04 |
| 计算设备 | `/dev/kfd`、`/dev/dri/renderD128`，权限 `crw-rw-rw-` |
| 显示设备 | `/dev/dri/card1`，`root:video 660`；纯计算通常不需要打开它 |

GPU 在 PCI 地址 `b3:00.0`。`rocm-smi` 显示空闲时处于低功耗状态，性能测试前必须预热。

## 2. Slurm 与“抢占式”真实含义

- hepnode0 的 Slurm 信息是 `Gres=(null)`；`GresTypes=gpu` 仅用于其他节点的 L40。
- **不能写 `--gpus` / `--gres=gpu` 来申请这块卡**。
- 分区 `PreemptMode=OFF`、`PreemptType=(null)`，所以**没有调度器抢占**。
- 实际可用方式是：提交普通 CPU 作业并固定 `-w hepnode0`；
  因为 `RealMemory=1` 导致一节点一作业，谁先拿到 hepnode0 的作业槽，谁就独占整个节点及 GPU。
- 若 hepnode0 已被别人作业占用，只能等待；不能用 Slurm 与另一个作业共享。
- **不要直接在登录 Shell 运行 GPU 计算**。用 `srun`/`sbatch` 占住节点，即使是短测试。
- 多个 Agent 不要同时尝试；GPU 没有 GRES/进程隔离，谁先启动进程谁用。队内需要人工协调。

最小申请模板：

```bash
srun -w hepnode0 -n1 -c4 --hint=nomultithread --time=00:10:00 \
  bash -lc 'source <worktree>/tmp/amd-gpu/env.sh; ...'
```

更推荐 `sbatch`，避免占用交互终端；完整模板：
`scripts/amd-gpu-smoke.slurm`。不写 `--mem`。

## 3. 不装 root、不用容器的最小 ROCm

系统没有预装 ROCm/HIP 用户库，但 Ubuntu 26.04 的软件源已有 ROCm 7.1.1 包。
`apt download` + `dpkg-deb -x` 到私有目录即可运行，**无需 sudo，也不修改 `/opt` 或共享 Python**。

已实测的安装：

```bash
# 在任意可访问已经配置好的 Ubuntu apt 源的机器/登录节点执行文件下载
scripts/setup_amd_rocm.sh
# 默认前缀：<worktree>/tmp/amd-gpu/root
source tmp/amd-gpu/env.sh
echo "$HIP_PATH $HIP_DEVICE_LIB_PATH"
```

脚本下载并解包：

```text
rocminfo, rocm-smi, librocm-smi64-7, libamd-smi26,
libhsa-runtime64-1, libhsakmt1, librocm-core1,
libamdhip64-7, libamdhip64-dev, libamd-comgr3, rocm-device-libs-21,
hipcc, clang-21, llvm-21, lld-21, clang-tools-21,
libclang-rt-21-dev, libclang-common-21-dev, libstdc++-16-dev
```

`env.sh` 设置 `HIP_PATH=$ROCM_PREFIX/usr`、`ROCM_PATH`、`HIP_DEVICE_LIB_PATH`、
`LD_LIBRARY_PATH`、`LIBRARY_PATH` 和工具 PATH。不要覆盖系统库或共享 venv。

编译 HIP：

```bash
source tmp/amd-gpu/env.sh
"$ROCM_PREFIX/usr/bin/hipcc" --offload-arch=gfx1201 -O3 \
  --rocm-path="$ROCM_PATH" \
  --rocm-device-lib-path="$HIP_DEVICE_LIB_PATH" \
  scripts/hip_probe.cpp -o tmp/amd-gpu/hip_probe
HIP_VISIBLE_DEVICES=0 tmp/amd-gpu/hip_probe
```

如果不显式给 `--rocm-device-lib-path`，hipcc 会报“cannot find ROCm device library”。
如果链接报 `cannot find -lamdhip64`，检查 `LIBRARY_PATH` 是否包含
`$ROCM_PREFIX/usr/lib/x86_64-linux-gnu`。

## 5. 容器结论

当前**不能直接使用自备 OCI/SIF 容器**：

- 系统没有 `docker/podman/apptainer/singularity/bwrap/newuidmap`；
- `unshare -Ur` 报 `write failed /proc/self/uid_map: Operation not permitted`；
- `kernel.apparmor_restrict_unprivileged_userns=1`；
- 普通用户没有权限安装 setuid helper 或修改 userns 策略。

Apptainer/Podman 软件包虽能下载，但没有 root/setuid/newuidmap 时不能可靠启动。
因此本报告不使用容器路线；上面的用户态 `.deb` 解包已经足够。

如果某些 Agent 必须要官方 Ubuntu 24.04 ROCm/PyTorch 容器，需要请管理员：
1. 允许无特权 user namespace（或安装带 setuid 的 Apptainer），或
2. 直接把 AMD GPU 暴露为 Slurm GRES 并提供系统 ROCm/CUDA 兼容环境。
在当前状态下，不要声称容器方案可直接运行。

## 6. 驱动/发行版兼容性风险

当前工作点是 **Ubuntu 26.04 + 内核 7.0.0-38 + ROCm 7.1.1 用户态包**。
AMD 官方当前 ROCm 文档把 R9700 (`gfx1201`) 列入支持列表，但官方 OS 支持表只列
Ubuntu 24.04/22.04、RHEL；**Ubuntu 26.04 不在官方 OS 支持范围**。
实测基础 HSA/HIP 可用，但不等于所有 ROCm 库、PyTorch wheel、性能计数器都官方支持。
任何新依赖应固定包版本并做功能验证，不能把“rocminfo 能识别”当成全栈兼容证明。

## 7. 使用边界与建议

- 这是**实验性共享资源**；节点0同时也是登录节点，必须通过 Slurm 占用，不要在登录 Shell 跑。
- `RealMemory=1` 使 node0 一次只能有一个作业；其他 GPU 路线会与 CPU/MPI 任务争用同一作业槽。
- GPU 没有 GRES 记录，无法用 `--gpus` 做资源计量；所有 Agent 需要自觉串行、短作业、用完退出。
- 立即把 GPU 用于 melspec 前，先在 `gfx1201` 上实现/验证 HIP FFT 或自写 kernel；
  不要复用 CUDA 源码；HIP 与 CUDA API 相近但设备端库/编译参数不同。
- 性能测试必须包含 H2D/D2H、同步、kernel、初始化；至少重复多次并区分低功耗到稳定频率的第一次运行。
- 可复现脚本：`scripts/setup_amd_rocm.sh`、`scripts/amd-gpu-smoke.slurm`、
  `scripts/hip_probe.cpp`；原始日志在 `versions/_cluster/raw-amd-r9700/`。
- 不把该路径的包、二进制或日志提交为 melspec 提交文件；它们是环境证据。

## 8. 给其他 Agent 的最短操作清单

```bash
# 1) 在各自 worktree 的 tmp 中安装私有运行时（一次性）
scripts/setup_amd_rocm.sh

# 2) 从登录节点提交，不要直接运行计算
sbatch -w hepnode0 scripts/amd-gpu-smoke.slurm
# 或 srun -w hepnode0 -n1 -c4 --hint=nomultithread --time=00:10:00 bash
# 然后 source tmp/amd-gpu/env.sh 并使用 hipcc/hip_probe

# 3) 确认输出出现 gfx1201 和 PASS 后才开始写正式 kernel
```

如果 hepnode0 被占用，等待作业结束；不能抢占已运行作业，也不能绕过 Slurm 在登录 Shell 直接跑。
