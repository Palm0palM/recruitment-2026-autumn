# P3：跨帧 Hann 三基底预调制（数学审查后停止，不实现）

目标：利用重叠帧，把每帧 Hann 计算转换为对整条音频一次预处理和逐帧线性组合。
这是等价计算重构假设，不是简单转置，也不是修改FFT kernel。

## 实数域等价性

令 ω=2π/N，绝对采样 s=tH+n，φt=ωtH。

```
y[s] w[n]
 = 0.5 y[s] - 0.5 y[s] cos(ωs-φt)
 = 0.5 y[s] - 0.5 cos(φt) * (y[s] cos(ωs))
                  - 0.5 sin(φt) * (y[s] sin(ωs)).
```

可以预先构造三条序列 y、yc=y*cos(ωs)、ys=y*sin(ωs)，帧内通过两个 FMA 组合。
若进一步利用 FFT 线性，则 Hann STFT 可以由三条矩形窗 STFT 的相位加权组合得出。
以上只在精确实数域严格等价；冻结代码的 double `cos(ωn)`、乘法和float截断顺序不同，
新方案有大绝对相位求值/相位递推误差与舍入差，不能声称 bit-exact。

## 流量和复杂度

| 项目 | 冻结/已选slab pack | 三基底方案 |
|---|---|---|
| 必要每帧样本算术 | FN次double乘法 | 至少2FN次乘加，另预处理约2S次乘法及相位求值 |
| 逻辑原始序列读取 | 8FN字节 | 至少24FN字节 |
| 原始数据布局 | 一条音频 / 有界slab | 三条音频或三份slab |
| 额外整条音频存储 | slab法无全量副本 | 至少16S字节 yc/ys |
| FFT方案 | 每帧一个N/2复FFT | 若基于FFT线性组合直接实现，变为三路FFT |

冻结实现已经预先生成window[n]，并非每帧计算cos；window广播开销很小。
因此所谓“预调制”并没有消除热点所需的乘法/加载，反而增加每帧算术和缓存压力。
改用矩形滑动DFT更新要对每个hop的输入/移出样本更新所有频点：朴素复杂度O(FHN)，
相较现有O(FN logN)在常见H>logN时更差；递推还有长输入漂移问题。

## 决策

**不实现。** 精确数学关系存在，但按当前接口与FFT固定约束，成本模型比已验证slab更差。
不为“激进”而引入三路STFT、近似窗口或依赖内容/固定官方H的展开。
没有实际二进制、benchmark或正确性成绩，不将此项列为已完成性能实验。

## 其他停止方向

- 单独Mel/NT store：完全删除Mel+store的上限仍不到3%，不值得添加对齐分支与sfence。
  输出B16已连续写128字节，后续main还会读取double做转换；不能假定NT一定有利。
- 线程/NUMA：cpuset0–15全属同一NUMA节点，worker负载均衡；无跨节点首触迁移证据。
- 软件prefetch：无PMU cache-miss证据，不根据猜测添加；slab已把热点改成连续SIMD加载。
- PGO/LTO：大头是受保护I/O/初始化和显式SIMD kernel；目前没有分支/内联瓶颈证据。
  不通过全程序编译技巧改变main生成的初始化来宣称算法收益。
