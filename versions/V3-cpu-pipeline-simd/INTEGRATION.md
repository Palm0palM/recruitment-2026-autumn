# 组合实验与数值诊断

源码/算法快照 `cbf214d`，只在本实验分支，不修改未来Hybrid。

## 额外严格检查的失败（作业364）

修复空batch引用后，slab和HP**各自**通过68组bit-exact检查与严格ASan/UBSan的24组API测试。
第三个配置（slab+HP同时启用）在合成DC案例60未满足bit-exact，因此作业按设计中止。
这不是官方容差FAIL，但仍保留完整失败日志，不把未完成的作业标为完成。

## 定位（作业374）

- N=2048、H=29、79帧、31mels，满幅DC；与官方参数无关。
- 不同元素300个，**全部在64..78尾帧**；0..63的B16结果完全相同。
- 最大差 `9.962912639512947e-29`，为本应接近零的残余能量；不存在NaN/Inf、帧错位或越界。
- 该差距比官方atol=1e-4小约24个数量级。
- 组合随后以原官方rtol/atol对照冻结B16与独立librosa，68组全部PASS。

尾帧源代码没有任何算术改动；差异符合新增代码引起编译器对未改FP64路径的代码生成/浮点
收缩选择变化。尚未通过逐指令追踪归因到某一条FMA，**不把具体FMA原因当作已证明事实**。
不存在通过识别DC、固定参数或放宽官方容差来“修复”结果；生产源码不因此改动。

## 后续验收规则

- 单项slab/HP继续强制bit-exact，以监测真正数据布局错误。
- 组合不承诺bit-exact，明确使用用户评测的原始rtol=1e-3、atol=1e-4，并同时对照独立librosa。
- 所有配置继续严格sanitizer、vector复用/非PCM double API测试、全量官方expected与validate。
- 完整进程性能只用未插桩二进制；单项收益不能相加，必须测组合及相对slab的增量。
- 若业务要求在当前工具链下逐位复现e448而不只是题目容差，选择已验证单项配置，不推荐组合。

## 完整集成作业380

68组合成对照、严格ASan/UBSan的24组API测试、官方完整validate四组全部PASS。
第一次组合8次AB/BA，elapsed减少20.80% / 14.63% / 18.76% / 19.52%。
另做相对slab单项的独立8次AB/BA，组合再减少16.12% / 6.94% / 13.56% / 14.68%。
这是直接测量增量，不是把两个单项百分比相加。

最终作业396再次8次AB/BA：组合减少20.81% / 14.55% / 18.35% / 19.70%；
两轮64对逐次时间组合全部更快。原始validate.py runs=3再获4/4 PASS，
时间`.643 / .412 / .841 / .800s`。stderr为空；源码/二进制SHA均在日志。
因此可作为官方数值容差下的可选组合交付，但保留上述bit-exact限制。
