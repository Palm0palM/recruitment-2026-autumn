# Batch=8 稳定节点后的增量优化

稳定基线见 [`../advanced/STABLE.md`](../advanced/STABLE.md)（标签 `v2-simd-batch8-stable`）。本轮不重复单帧 AVX-512、j=0 或 j 外层实验，所有候选均与该节点或其后续独立提交比较。

## 1. Mel 支持区间裁剪（提交 `422c2fb`，作业 208）

只计算所有 Mel 三角滤波器实际读取的连续 bin 区间，未使用的功率谱不计算。范围由参数和滤波器定义决定，与音频内容无关。

| 用例 | 稳定 Batch=8 median (s) | 支持裁剪 median (s) | 改善 |
|---|---:|---:|---:|
| default | 0.891650 | 0.875940 | 1.8% |
| small_mels | 0.543602 | 0.532048 | 2.1% |
| large_fft | 1.202986 | 1.155278 | 4.0% |
| narrow_band | 1.182128 | 1.132005 | 4.2% |

四组全部 PASS。阶段 profile 显示恢复成本：default 从 18,227 降至 8,515 ns/batch，large_fft 从 52,148 降至 20,392 ns/batch。其余阶段只有运行波动，收益与跳过未使用 bin 相符。

## 2. 原位功率谱与对称恢复（提交 `aa2405b`，作业 214）

低频支持范围内，读取 `re[k]` 与 `re[half-k]` 后即可用 `power[k]` 覆盖 `re[k]`，不再需要独立 power 数组。全 Nyquist 情况不能逐 k 覆盖，因为对称项仍需旧值，因此成对读取并计算 k 与 half-k 后写回。第二路虚部差分符号单独推导，CLI 默认全频谱也纳入回归。

Batch=8 大 FFT 的 re/im/power 活跃缓冲区由约 1.5 MiB 降为 re/im 约 1.0 MiB，并消除第三个数组的初始化。

| 用例 | 支持裁剪 median (s) | 原位融合 median (s) | 改善 |
|---|---:|---:|---:|
| default | 0.870256 | 0.864017 | 0.7% |
| small_mels | 0.528108 | 0.523456 | 0.9% |
| large_fft | 1.149722 | 1.133168 | 1.4% |
| narrow_band | 1.122202 | 1.115651 | 0.6% |

四组全部 PASS，ASan 默认与 CLI 用例通过。大 FFT 恢复阶段进一步从 20,392 降至 15,442 ns/batch。调试中保留了两个真实边界问题：Nyquist 需要 re 的 n+1 项，以及全频谱覆盖会破坏对称输入；最终版本均通过。

## 3. 连续输入打包：未采用（micro 作业 223）

实验 B 每帧连续加载 16 个音频和 16 个 Hann double，乘法后去偶奇交错，再做 8×8 转置和位反转写出。初版转置控制字错误导致验证失败，修正为 `0x88/0xdd` 后所有 re/im 误差为 0。有效结果：

| half N | 当前 setr pack ns/frame | 连续+转置 ns/frame | 结论 |
|---|---:|---:|---|
| 4096 | 约 4,000 | 约 4,390 | 慢约 10%，不采用 |
| 8192 | 约 9,220 | 约 9,300 | 基本持平略慢，不采用 |

连续加载减少了标量流拼装，但两次 8×8 转置抵消收益。该路径不进入正式实现，保留 micro 作为后续对照。

## 4. 成对谱恢复 micro：只保留必要回退

独立 recovery micro 验证 full/support46/support17 全部通过。full-range 成对处理将读取量约减半，但性能随 FFT 尺寸变化：

- n=4096：逐 k 约 2,184 ns/frame，成对约 2,004 ns/frame，成对更快。
- n=8192：逐 k 约 6,015 ns/frame，成对约 6,486 ns/frame，成对更慢。
- 支持区间内两种实现都退化为单路，时间与读取量基本一致。

因此不把成对处理扩大为所有场景的统一优化；它只在原位融合需要保持全频谱正确性时使用。

## 5. 当前最佳

当前最佳为 `aa2405b`：Batch=8 + Mel 支持裁剪 + 原位功率谱。后续 DIF 只先做独立 microbenchmark；连续打包的负结果不作为继续重构的理由。所有原始逐次时间、profile 和 micro 数据见 `raw/`。
